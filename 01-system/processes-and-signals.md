# Processes and signals

## 1. What is a process?

A process is a running instance of a program. The kernel assigns it a process ID (**PID**) and tracks its state, credentials, resources, and relationships to other processes.

Useful terms:

- **PID:** Process ID.
- **PPID:** Parent process ID.
- **UID / user:** User identity under which the process runs.
- **Foreground/background:** Whether a process is interacting with the current shell job control.
- **Signal:** A notification sent to a process, often to request termination or another action.
- **Zombie:** A process that has exited but whose parent has not yet collected its exit status.

On a systemd-managed server, services should normally be managed with `systemctl`, not by manually killing their main PID.

## 2. List processes with `ps`

`ps` displays a snapshot of selected processes. Use `top` or another monitor for a continuously updating view.

```bash
ps
ps aux
ps -ef
```

The `aux` and `-ef` forms use different historical option styles.

### Useful process selection and output options

| Option | Meaning |
|---|---|
| `a` | BSD-style selection that includes processes associated with terminals, subject to `ps` selection rules. |
| `u` | BSD-style user-oriented output format. |
| `x` | Include processes without a controlling terminal. |
| `-e` | Select all processes. |
| `-f` | Use a full-format listing. |
| `-o <format>` | Choose output columns. |
| `--sort=<key>` | Sort by a selected output field. Prefix a field with `-` for descending order. |

Examples:

```bash
ps -eo pid,ppid,user,stat,%cpu,%mem,cmd --sort=-%cpu
ps -eo pid,ppid,user,stat,cmd --sort=pid
```

Useful `ps` columns:

| Column | Meaning |
|---|---|
| `PID` | Process ID. |
| `PPID` | Parent process ID. |
| `USER` | Effective user name in common formats. |
| `STAT` | Process state and supplementary state characters. |
| `%CPU` | CPU utilization as reported by `ps`; interpretation is not identical to a long-term performance metric. |
| `%MEM` | Resident memory as a percentage of physical memory. |
| `CMD` | Command line or command name, depending on output format. |

## 3. Find a process by name or PID

### `pgrep` — search process IDs

| Option | Meaning |
|---|---|
| `-a` | Show the full command line with each matching PID. |
| `-f` | Match against the full command line rather than only the process name. |
| `-u <user>` | Match processes owned by the specified effective user. |
| `-x` | Require an exact process-name match. |

```bash
pgrep -a sshd
pgrep -af 'python3 /srv/app'
pgrep -u www-data -a
```

### `pidof` — find process IDs by program name

```bash
pidof sshd
```

`pidof` may return one or more PIDs, depending on the program and its process model. It is not a universal way to identify a systemd service's complete process tree.

### `pstree` — display process relationships

```bash
pstree
pstree -p
pstree -ap <PID>
```

| Option | Meaning |
|---|---|
| `-p` | Include PIDs. |
| `-a` | Show command-line arguments where available. |

## 4. Monitor processes with `top`

```bash
top
```

| Option | Meaning |
|---|---|
| `-u <user>` | Show processes for the specified user. |
| `-p <PID>` | Monitor the specified PID or PIDs. |
| `-b` | Batch mode, suitable for scripts or captured output. |
| `-n <count>` | Exit after the specified number of refreshes. |
| `-d <seconds>` | Set the refresh delay. |

Useful interactive keys in `top` commonly include:

| Key | Action |
|---|---|
| `q` | Quit. |
| `P` | Sort by CPU usage. |
| `M` | Sort by memory usage. |
| `k` | Prompt to send a signal to a process. Use carefully. |
| `1` | Toggle per-CPU summary display. |
| `h` | Show help. |

## 5. Process states

The `STAT` column from `ps` commonly uses these state letters:

| State | Meaning |
|---|---|
| `R` | Running or runnable. |
| `S` | Interruptible sleep. |
| `D` | Uninterruptible sleep, commonly waiting for I/O. |
| `T` | Stopped, often by job control or a signal. |
| `Z` | Zombie: exited, but not yet reaped by its parent. |
| `I` | Idle kernel thread on systems where this state is reported. |

Additional letters may indicate properties such as multithreading, session leadership, or priority.

A process in `D` state may not react to ordinary termination signals until the kernel operation it is waiting for completes. Repeatedly sending `SIGKILL` does not solve the underlying I/O or kernel wait.

## 6. Signals and `kill`

A signal is a notification delivered to a process. Signals can request termination, pause or continue a process, or communicate other events.

### Common signals

| Signal | Meaning |
|---|---|
| `SIGHUP` | Hangup; some daemons interpret it as a request to reload configuration, but this is application-specific. |
| `SIGINT` | Interrupt from the terminal, commonly generated by `Ctrl+C`. |
| `SIGTERM` | Request graceful termination; the default signal used by `kill`. |
| `SIGKILL` | Force termination; cannot be caught, blocked, or ignored. |
| `SIGSTOP` | Stop a process; cannot be caught, blocked, or ignored. |
| `SIGCONT` | Continue a stopped process. |

### `kill` — send a signal to a PID

Sending a signal changes process state.

```bash
kill -<SINGAL> <PID>
kill -l
```

| Option / argument | Meaning |
|---|---|
| `-l` | List signal names, or translate a signal number/name. |
| `-0` | Send no signal; perform permission and process-existence checks. It does not prove the process is healthy. |

Prefer graceful termination first:

```bash
kill -TERM <PID>
```

**Warning — high impact:** `SIGKILL` prevents the process from cleaning up, flushing application data, or removing temporary state. It can leave files, locks, or transactions requiring recovery.

### `pkill` — send a signal by process match

This can affect multiple matching processes. Check the process match carefully before sending a signal.

```bash
pkill -TERM -x example-daemon
```

| Option | Meaning |
|---|---|
| `-TERM` | Select the signal to send. |
| `-x` | Match the process name exactly. |
| `-u <user>` | Restrict matches to a user. |
| `-f` | Match the full command line; use with particular care. |

Preview matches before signaling:

```bash
pgrep -a -x example-daemon
```

## 7. Change process priority

Linux scheduling priority and nice values affect CPU scheduling behavior for normal scheduling policies. They do not reserve CPU time or fix resource bottlenecks.
The nice value can range from -20 to 19, with 19 being the lowest priority. 

### `nice`

This starts the command with a changed scheduling priority.

```bash
nice -n 10 command --argument
```

A higher nice value means a lower scheduling priority for normal processes. Raising priority by lowering the nice value generally requires elevated privilege.

### `renice`

Changing another user’s process or increasing its priority may require root privileges.

```bash
renice 10 -p <PID>
renice -n 5 -p <PID>
```

## 8. Manage service processes through systemd

For a process owned by a systemd service, prefer the service manager:

```bash
systemctl status <service>
sudo systemctl stop <service>
sudo systemctl restart <service>
```

This allows systemd to apply the unit's configured stop behavior, dependencies, and restart policy. Manually killing a daemon can cause systemd to restart it or leave the service in an unexpected state.
